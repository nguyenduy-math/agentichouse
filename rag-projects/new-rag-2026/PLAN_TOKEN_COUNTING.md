# Per-Session Token Counting — Implementation Plan

**Project:** new-rag-2026  
**Date:** 2026-06-07  
**Status:** Planning

---

## 1. Overview

Per-session token counting attributes every LLM call made during a chat turn to the session that triggered it. This gives the system three capabilities it currently lacks:

**Cost attribution per session.** The SQLite `turns` table already groups turns by `session_id`. Adding a `token_usage` table alongside it lets you answer "how much did this session cost?" without relying on LangSmith or any external service.

**Identification of expensive query patterns.** Breaking usage down by `call_type` (e.g. `query_rewrite`, `classify`, `domain_answer_hr`, `synthesize`, `verify_domain`, `verify_final`) exposes which pipeline steps are token-hungry. If `domain_answer_benefits` consistently uses 5× more tokens than `classify`, that signals an over-engineered prompt or a retrieval problem returning too much context.

**Provider/model comparison.** The system supports three LLM providers — `gemini`, `openai`, and `siliconflow` — and can be switched via `LLM_PROVIDER`. Token cost per provider varies significantly (Gemini Flash is ~15× cheaper per token than GPT-4o). Storing `provider` + `model` per call makes it possible to quantify this difference from real traffic.

The implementation is additive: no existing code is deleted or changed in behavior. All new components are wired in around the existing `RunnableConfig` propagation path that already connects `chat.py → orchestrator.py → domain agents → verification_service.py`.

## 2. SQLite Schema Extension

Add the `token_usage` table to the same `data/history.db` file managed by `HistoryStore`. Extend `SCHEMA_SQL` in `backend/app/services/history_store.py`:

```python
SCHEMA_SQL = """
-- ... existing CREATE TABLE turns ...
-- ... existing CREATE TABLE eval_runs ...
-- ... existing CREATE TABLE eval_run_scores ...

CREATE TABLE IF NOT EXISTS token_usage (
    id                INTEGER PRIMARY KEY AUTOINCREMENT,
    session_id        TEXT    NOT NULL,
    turn_id           TEXT,                -- nullable: pre-turn or session-init calls
    call_type         TEXT    NOT NULL,    -- see § 3 for valid values
    provider          TEXT    NOT NULL,    -- gemini | openai | siliconflow
    model             TEXT    NOT NULL,    -- e.g. gemini-2.0-flash, gpt-4o
    prompt_tokens     INTEGER NOT NULL DEFAULT 0,
    completion_tokens INTEGER NOT NULL DEFAULT 0,
    total_tokens      INTEGER NOT NULL DEFAULT 0,
    cost_usd          REAL    NOT NULL DEFAULT 0.0,
    error             INTEGER NOT NULL DEFAULT 0,  -- 1 if on_llm_error fired
    timestamp         TEXT    NOT NULL
);

CREATE INDEX IF NOT EXISTS idx_token_session ON token_usage(session_id);
CREATE INDEX IF NOT EXISTS idx_token_turn    ON token_usage(turn_id);
CREATE INDEX IF NOT EXISTS idx_token_type    ON token_usage(call_type);
"""
```

**Why `cost_usd` is stored eagerly (not computed on read):** pricing tables change over time. Storing the cost at call-time preserves historical accuracy when model pricing is updated later.

**Why `error` column:** `on_llm_error()` fires when a provider call fails. Recording failed calls with `error=1` and `0` tokens keeps the table as a complete audit trail of all LLM attempts, not just successful ones.

The `turn_id` FK is nullable because `VerificationService` calls that happen as part of a turn are identified by `session_id` only — the `turn_id` is generated by `history_store.save_turn()` which runs asynchronously *after* the orchestrator completes. The wiring in §6 explains how to bridge this.

## 3. `SessionTokenCallback` — Full Design

Create `backend/app/services/token_callback.py`:

```python
"""
LangChain callback handler that attributes token usage to a specific session and call type.

A new instance is created per (session_id, call_type) pair in the chat router.
All instances for a single chat turn share the same session_id and turn_id.
"""
from __future__ import annotations

import asyncio
import logging
from datetime import datetime, timezone
from typing import TYPE_CHECKING, Any

from langchain_core.callbacks import BaseCallbackHandler
from langchain_core.outputs import LLMResult

if TYPE_CHECKING:
    from app.services.history_store import HistoryStore

logger = logging.getLogger(__name__)

# Valid call_type labels — keep in sync with orchestrator step names
CALL_TYPES = frozenset({
    "query_rewrite",
    "classify",
    "domain_answer_hr",
    "domain_answer_benefits",
    "domain_answer_finance",
    "domain_answer_compliance",
    "domain_answer_it",
    "domain_answer_procedures",
    "domain_answer_general",
    "synthesize",
    "verify_domain",
    "verify_final",
})


class SessionTokenCallback(BaseCallbackHandler):
    """
    Captures on_llm_end / on_llm_error and persists token usage to SQLite.

    Thread safety: all instance state is set at construction time and never mutated.
    Async writes use asyncio.create_task() so they never block the LLM response path.
    """

    raise_error = False  # do not propagate callback exceptions to the caller

    def __init__(
        self,
        session_id: str,
        call_type: str,
        token_store: "HistoryStore",
        provider: str,
        model: str,
        turn_id: str | None = None,
    ) -> None:
        super().__init__()
        self.session_id = session_id
        self.call_type = call_type
        self._store = token_store
        self.provider = provider
        self.model = model
        self.turn_id = turn_id  # set retroactively via set_turn_id()

    def set_turn_id(self, turn_id: str) -> None:
        """Called after history_store.save_turn() resolves its UUID."""
        self.turn_id = turn_id

    # ------------------------------------------------------------------
    # LangChain hook: successful completion
    # ------------------------------------------------------------------

    def on_llm_end(self, response: LLMResult, **kwargs: Any) -> None:
        prompt_tokens, completion_tokens = _extract_tokens(response, self.provider)
        total_tokens = prompt_tokens + completion_tokens
        cost = _estimate_cost(self.provider, self.model, prompt_tokens, completion_tokens)

        asyncio.create_task(
            self._store.log_tokens(
                session_id=self.session_id,
                turn_id=self.turn_id,
                call_type=self.call_type,
                provider=self.provider,
                model=self.model,
                prompt_tokens=prompt_tokens,
                completion_tokens=completion_tokens,
                total_tokens=total_tokens,
                cost_usd=cost,
                error=False,
            )
        )

    # ------------------------------------------------------------------
    # LangChain hook: provider error
    # ------------------------------------------------------------------

    def on_llm_error(self, error: BaseException, **kwargs: Any) -> None:
        logger.warning(
            "LLM error captured by SessionTokenCallback",
            extra={"session_id": self.session_id, "call_type": self.call_type, "error": str(error)},
        )
        asyncio.create_task(
            self._store.log_tokens(
                session_id=self.session_id,
                turn_id=self.turn_id,
                call_type=self.call_type,
                provider=self.provider,
                model=self.model,
                prompt_tokens=0,
                completion_tokens=0,
                total_tokens=0,
                cost_usd=0.0,
                error=True,
            )
        )


# ------------------------------------------------------------------
# Token extraction — provider-specific response formats
# ------------------------------------------------------------------

def _extract_tokens(response: LLMResult, provider: str) -> tuple[int, int]:
    """
    Extract (prompt_tokens, completion_tokens) from LLMResult.

    Provider differences:
    - OpenAI / Siliconflow (OpenAI-compatible):
        response.llm_output["token_usage"] = {
            "prompt_tokens": int,
            "completion_tokens": int,
            "total_tokens": int,
        }
    - Gemini (langchain-google-genai):
        response.llm_output["usage_metadata"] = {
            "prompt_token_count": int,
            "candidates_token_count": int,
            "total_token_count": int,
        }
    """
    if not response.llm_output:
        return 0, 0

    if provider == "gemini":
        meta = response.llm_output.get("usage_metadata", {})
        return (
            meta.get("prompt_token_count", 0),
            meta.get("candidates_token_count", 0),
        )

    # openai + siliconflow (OpenAI-compatible endpoint)
    usage = response.llm_output.get("token_usage", {})
    return (
        usage.get("prompt_tokens", 0),
        usage.get("completion_tokens", 0),
    )
```

**Why `raise_error = False`:** LangChain will silently drop callback exceptions when this is set. Since token logging is a side-effect (not part of the answer), it must never crash the response path.

**Why store `provider` + `model` on the callback rather than reading from `kwargs`:** `kwargs.get("invocation_params", {})` is not stable across LangChain versions and differs by provider. The chat router already knows the provider from `settings.LLM_PROVIDER` and the model from the env var — it's cleaner to pass them explicitly at construction time.

## 4. Cost Estimation

Add `_estimate_cost()` and `COST_PER_1K` to the same `token_callback.py` file:

```python
# Prices in USD per 1,000 tokens: (prompt_cost, completion_cost)
# Source: provider pricing pages as of 2026-06
COST_PER_1K: dict[tuple[str, str], tuple[float, float]] = {
    ("openai",      "gpt-4o"):                              (0.0025,  0.0100),
    ("openai",      "gpt-4o-mini"):                         (0.00015, 0.00060),
    ("gemini",      "gemini-2.0-flash"):                    (0.00010, 0.00040),
    ("gemini",      "gemini-2.5-flash"):                    (0.00015, 0.00060),
    ("gemini",      "gemini-2.5-pro"):                      (0.00125, 0.01000),
    ("siliconflow", "deepseek-ai/DeepSeek-V3"):             (0.00014, 0.00028),
    ("siliconflow", "Qwen/Qwen2.5-72B-Instruct"):           (0.00040, 0.00040),
    ("siliconflow", "BAAI/bge-large-zh-v1.5"):              (0.00000, 0.00000),  # embed only
}


def _estimate_cost(
    provider: str, model: str, prompt_tokens: int, completion_tokens: int
) -> float:
    """Return estimated cost in USD. Returns 0.0 for unknown models."""
    key = (provider, model)
    if key not in COST_PER_1K:
        return 0.0
    prompt_rate, completion_rate = COST_PER_1K[key]
    return (prompt_tokens / 1000 * prompt_rate) + (completion_tokens / 1000 * completion_rate)
```

Update the pricing table whenever a new provider or model is added to `llm_service.py`.

## 5. `TokenStore` Methods in `HistoryStore`

Add the following methods to the `HistoryStore` class in `backend/app/services/history_store.py`. They follow the exact same aiosqlite pattern as `save_turn()` and `save_eval_run()`.

```python
# ── Token usage ──────────────────────────────────────────────────────────────

async def log_tokens(
    self,
    session_id: str,
    call_type: str,
    provider: str,
    model: str,
    prompt_tokens: int,
    completion_tokens: int,
    total_tokens: int,
    cost_usd: float,
    error: bool,
    turn_id: str | None = None,
) -> None:
    """Persist one LLM call's token usage. Called from SessionTokenCallback."""
    try:
        async with aiosqlite.connect(self._db_path) as db:
            await db.execute(
                """
                INSERT INTO token_usage
                    (session_id, turn_id, call_type, provider, model,
                     prompt_tokens, completion_tokens, total_tokens,
                     cost_usd, error, timestamp)
                VALUES (?, ?, ?, ?, ?, ?, ?, ?, ?, ?, ?)
                """,
                (
                    session_id,
                    turn_id,
                    call_type,
                    provider,
                    model,
                    prompt_tokens,
                    completion_tokens,
                    total_tokens,
                    cost_usd,
                    int(error),
                    datetime.now(timezone.utc).isoformat(),
                ),
            )
            await db.commit()
    except Exception as exc:
        logger.error("log_tokens_failed", error=str(exc), session_id=session_id)


async def get_session_token_summary(self, session_id: str) -> dict:
    """
    Returns totals, by_call_type, by_model, and per-turn breakdown
    for a single session.
    """
    async with aiosqlite.connect(self._db_path) as db:
        db.row_factory = aiosqlite.Row

        # Totals
        cursor = await db.execute(
            """
            SELECT
                SUM(prompt_tokens)     AS total_prompt,
                SUM(completion_tokens) AS total_completion,
                SUM(total_tokens)      AS total_tokens,
                SUM(cost_usd)          AS total_cost_usd,
                COUNT(*)               AS total_calls
            FROM token_usage
            WHERE session_id = ? AND error = 0
            """,
            (session_id,),
        )
        totals = dict(await cursor.fetchone() or {})

        # By call_type
        cursor = await db.execute(
            """
            SELECT call_type,
                   SUM(total_tokens) AS total_tokens,
                   SUM(cost_usd)     AS cost_usd,
                   COUNT(*)          AS calls
            FROM token_usage
            WHERE session_id = ? AND error = 0
            GROUP BY call_type
            ORDER BY total_tokens DESC
            """,
            (session_id,),
        )
        by_call_type = [dict(r) for r in await cursor.fetchall()]

        # By model
        cursor = await db.execute(
            """
            SELECT provider, model,
                   SUM(prompt_tokens)     AS prompt_tokens,
                   SUM(completion_tokens) AS completion_tokens,
                   SUM(total_tokens)      AS total_tokens,
                   SUM(cost_usd)          AS cost_usd
            FROM token_usage
            WHERE session_id = ? AND error = 0
            GROUP BY provider, model
            ORDER BY total_tokens DESC
            """,
            (session_id,),
        )
        by_model = [dict(r) for r in await cursor.fetchall()]

        # Per-turn breakdown (join with turns table)
        cursor = await db.execute(
            """
            SELECT tu.turn_id,
                   t.turn_number,
                   SUM(tu.total_tokens) AS total_tokens,
                   SUM(tu.cost_usd)     AS cost_usd,
                   COUNT(*)             AS calls
            FROM token_usage tu
            LEFT JOIN turns t ON tu.turn_id = t.turn_id
            WHERE tu.session_id = ? AND tu.error = 0 AND tu.turn_id IS NOT NULL
            GROUP BY tu.turn_id, t.turn_number
            ORDER BY t.turn_number ASC
            """,
            (session_id,),
        )
        turn_breakdown = [dict(r) for r in await cursor.fetchall()]

    return {
        "session_id": session_id,
        "total_prompt_tokens":     totals.get("total_prompt", 0),
        "total_completion_tokens": totals.get("total_completion", 0),
        "total_tokens":            totals.get("total_tokens", 0),
        "total_cost_usd":          round(totals.get("total_cost_usd", 0.0) or 0.0, 6),
        "total_calls":             totals.get("total_calls", 0),
        "by_call_type":            by_call_type,
        "by_model":                by_model,
        "turn_breakdown":          turn_breakdown,
    }


async def get_all_sessions_token_summary(self, limit: int = 100) -> list[dict]:
    """Per-session totals for admin overview, ordered by cost descending."""
    async with aiosqlite.connect(self._db_path) as db:
        db.row_factory = aiosqlite.Row
        cursor = await db.execute(
            """
            SELECT session_id,
                   SUM(total_tokens) AS total_tokens,
                   SUM(cost_usd)     AS total_cost_usd,
                   COUNT(*)          AS total_calls,
                   MIN(timestamp)    AS first_call,
                   MAX(timestamp)    AS last_call
            FROM token_usage
            WHERE error = 0
            GROUP BY session_id
            ORDER BY total_cost_usd DESC
            LIMIT ?
            """,
            (limit,),
        )
        return [dict(r) for r in await cursor.fetchall()]
```

### 6.2 Why All Callbacks Get All Call Types

When LangChain propagates `RunnableConfig.callbacks` through a chain, **every callback fires for every LLM call**. There is no built-in per-step filtering. The naive solution — putting all callbacks in the list — means each `on_llm_end` fires 12 times (once per callback instance). That is wrong.

**Correct approach: one callback per call_type, use `run_name` to route.**

Refactor `SessionTokenCallback` to receive all valid call types and dispatch by matching the `run_name` from kwargs:

```python
class SessionTokenCallback(BaseCallbackHandler):
    """
    Single callback instance per session. Routes to correct call_type by
    matching the LangChain run_name passed in on_llm_start.
    """
    raise_error = False

    def __init__(
        self,
        session_id: str,
        token_store: "HistoryStore",
        provider: str,
        model: str,
        turn_id: str | None = None,
    ) -> None:
        super().__init__()
        self.session_id = session_id
        self._store = token_store
        self.provider = provider
        self.model = model
        self.turn_id = turn_id
        self._active_run_types: dict[str, str] = {}  # run_id → call_type

    def on_llm_start(
        self, serialized: dict, prompts: list[str], *, run_id, parent_run_id=None, tags=None, metadata=None, **kwargs
    ) -> None:
        # LangChain passes run_name (the chain step name) in kwargs or metadata
        run_name = (metadata or {}).get("call_type") or kwargs.get("name", "unknown")
        self._active_run_types[str(run_id)] = run_name

    def on_llm_end(self, response: LLMResult, *, run_id, **kwargs) -> None:
        call_type = self._active_run_types.pop(str(run_id), "unknown")
        prompt_tokens, completion_tokens = _extract_tokens(response, self.provider)
        total_tokens = prompt_tokens + completion_tokens
        cost = _estimate_cost(self.provider, self.model, prompt_tokens, completion_tokens)
        asyncio.create_task(self._store.log_tokens(
            session_id=self.session_id,
            turn_id=self.turn_id,
            call_type=call_type,
            provider=self.provider,
            model=self.model,
            prompt_tokens=prompt_tokens,
            completion_tokens=completion_tokens,
            total_tokens=total_tokens,
            cost_usd=cost,
            error=False,
        ))

    def on_llm_error(self, error: BaseException, *, run_id, **kwargs) -> None:
        call_type = self._active_run_types.pop(str(run_id), "unknown")
        asyncio.create_task(self._store.log_tokens(
            session_id=self.session_id, turn_id=self.turn_id, call_type=call_type,
            provider=self.provider, model=self.model,
            prompt_tokens=0, completion_tokens=0, total_tokens=0,
            cost_usd=0.0, error=True,
        ))
```

### 6.3 Passing `call_type` Through Orchestrator

Each LLM `.ainvoke()` call in the orchestrator needs to carry `call_type` in the config metadata so `on_llm_start` can read it. Create a helper:

```python
# backend/app/agents/orchestrator.py  (add near top)

def _step_config(base_config: RunnableConfig | None, call_type: str) -> RunnableConfig | None:
    """Return a config copy with call_type injected into metadata."""
    if base_config is None:
        return None
    meta = dict(base_config.get("metadata") or {})
    meta["call_type"] = call_type
    return {**base_config, "metadata": meta}
```

Then replace each bare `config` argument in orchestrator LLM calls:

```python
# _rewrite_query
response = await self._llm.ainvoke(
    [HumanMessage(content=prompt)],
    config=_step_config(config, "query_rewrite"),
)

# _classify
response = await self._llm.ainvoke(
    [HumanMessage(content=prompt)],
    config=_step_config(config, "classify"),
)

# _synthesize
response = await self._llm.ainvoke(
    [HumanMessage(content=prompt)],
    config=_step_config(config, "synthesize"),
)
```

Each domain agent's `answer()` method should similarly inject `call_type=f"domain_answer_{domain_key}"` via its own `_step_config()` call before forwarding to `self._llm.ainvoke()`. The `domain_key` is already available in each agent class.

`VerificationService.verify()` currently does not accept a `config` parameter. Two options:
- **Option A (preferred):** Add `config: RunnableConfig | None = None` to `VerificationService.verify()` and pass `_step_config(config, "verify_domain")` / `_step_config(config, "verify_final")` from the orchestrator.
- **Option B (simpler):** Accept that verification calls log as `call_type="unknown"` in Phase 1 and add config threading to `VerificationService` in Phase 2.

## 7. New API Endpoints

Add `backend/app/routers/tokens.py` (new file, pattern mirrors `eval.py`):

```python
"""Token usage endpoints."""
from __future__ import annotations

from fastapi import APIRouter, HTTPException, Request
from pydantic import BaseModel

router = APIRouter(prefix="/api/v1")


# ── Response schemas ──────────────────────────────────────────────────────────

class CallTypeBreakdown(BaseModel):
    call_type: str
    total_tokens: int
    cost_usd: float
    calls: int

class ModelBreakdown(BaseModel):
    provider: str
    model: str
    prompt_tokens: int
    completion_tokens: int
    total_tokens: int
    cost_usd: float

class TurnBreakdown(BaseModel):
    turn_id: str
    turn_number: int | None
    total_tokens: int
    cost_usd: float
    calls: int

class SessionTokenSummary(BaseModel):
    session_id: str
    total_prompt_tokens: int
    total_completion_tokens: int
    total_tokens: int
    total_cost_usd: float
    total_calls: int
    by_call_type: list[CallTypeBreakdown]
    by_model: list[ModelBreakdown]
    turn_breakdown: list[TurnBreakdown]

class AdminTokenRow(BaseModel):
    session_id: str
    total_tokens: int
    total_cost_usd: float
    total_calls: int
    first_call: str
    last_call: str


# ── Endpoints ─────────────────────────────────────────────────────────────────

@router.get("/sessions/{session_id}/tokens", response_model=SessionTokenSummary)
async def get_session_tokens(session_id: str, request: Request) -> SessionTokenSummary:
    history_store = getattr(request.app.state, "history_store", None)
    if history_store is None:
        raise HTTPException(status_code=503, detail="History store not available.")
    summary = await history_store.get_session_token_summary(session_id)
    return SessionTokenSummary(**summary)


@router.get("/admin/tokens/summary", response_model=list[AdminTokenRow])
async def get_admin_token_summary(
    request: Request, limit: int = 100
) -> list[AdminTokenRow]:
    history_store = getattr(request.app.state, "history_store", None)
    if history_store is None:
        raise HTTPException(status_code=503, detail="History store not available.")
    rows = await history_store.get_all_sessions_token_summary(limit=limit)
    return [AdminTokenRow(**r) for r in rows]
```

Register the new router in `backend/app/main.py` (or wherever routers are registered):

```python

```

## 9. LangSmith Integration Note

LangSmith is already wired via `@traceable` decorators on `orchestrator_run`, `orchestrator_classify`, and `orchestrator_synthesize`. LangSmith traces already show token counts per span when using LangChain's native tracing.

The `SessionTokenCallback` provides the **same data locally** without requiring a LangSmith account, network access to `api.smith.langchain.com`, or any external dependency. The two systems are complementary:

- **LangSmith:** per-call prompt/completion text, latency waterfall, detailed debugging. Best for development.
- **Local SQLite via `SessionTokenCallback`:** session-level cost attribution, turn-level aggregation, admin overview, in-app UI. Works in air-gapped or cost-constrained deployments.

No changes to the existing `@traceable` setup are required. The callback and LangSmith tracing coexist because LangChain's callback system and the LangSmith client are independent.

## 10. Implementation Order

Execute in this sequence to keep the codebase in a working state at each step:

1. **Schema migration** — extend `SCHEMA_SQL` in `history_store.py` with the `token_usage` table and indexes. Run `initialize()` once (idempotent due to `IF NOT EXISTS`). No other code changes.

2. **`HistoryStore` write method** — add `log_tokens()` to `HistoryStore`. No callers yet. Add a unit test: call `log_tokens()`, then query the DB directly to confirm the row exists with correct values.

3. **`HistoryStore` read methods** — add `get_session_token_summary()` and `get_all_sessions_token_summary()`. Unit test with fixture data: insert 3 rows across 2 sessions, assert aggregation is correct.

4. **`token_callback.py`** — implement `SessionTokenCallback` with `on_llm_start`, `on_llm_end`, `on_llm_error`. Unit test by mocking `LLMResult` with Gemini-format and OpenAI-format `llm_output` and asserting `log_tokens()` is called with correct arguments.

5. **`_step_config()` helper** — add to `orchestrator.py`. Wrap each `self._llm.ainvoke()` call with the appropriate `call_type`. This is a pure metadata change — no functional difference if callbacks list is empty.

6. **Wire callback into `chat.py`** — construct one `SessionTokenCallback` per session per request, add to `RunnableConfig.callbacks`. Deploy to dev. Verify rows appear in `token_usage` after a chat request using `sqlite3 data/history.db "SELECT * FROM token_usage LIMIT 5;"`.

7. **Wire `turn_id` back-fill** — after `history_store.save_turn()` resolves, call `cb.set_turn_id(turn_id)` on all callbacks. Verify `turn_breakdown` in read queries is non-empty.

8. **Thread `config` into `VerificationService`** — add `config: RunnableConfig | None = None` parameter and pass `_step_config(config, "verify_domain")` / `_step_config(config, "verify_final")` from the orchestrator.

9. **Token API endpoints** — add `routers/tokens.py`, register in `main.py`. Test with `curl` or the existing `frontend/src/api/` client pattern.

10. **Frontend: admin token summary** — fetch `GET /api/v1/admin/tokens/summary` in the eval/admin page and display session totals.

11. **Frontend: `TokenSummaryPanel`** — fetch `GET /api/v1/sessions/{id}/tokens` and render the bar chart + turn table when a session is selected.

12. **Frontend: `MessageBubble` token chip** — join turn token data client-side and render the collapsed accordion on each assistant bubble.
